# v1.0 开发上下文摘要（forge-dev Discussion）

> forge-dev 第 1 步产物：把 PRD 没写到的「怎么做」灰区收拢成默认值，传给 forge-design-impl、forge-eng、forge-qa。迭代结项后归档到 `docs/archive/raw/`。

## 输入

- 产品当前事实：[PRD.md](PRD.md) v1.0
- 行为契约：[Feature Spec](../.features/pomodoro-timer/feature-spec.md)（R1–R6 + 验收检查表）
- 设计真相源：[DESIGN.md](DESIGN.md) v1.0 + 根目录 `pomodoro.tokens.css`（工作台导出，勿手改）
- 项目类型：**frontend**（纯静态页面，无后端）

## 视觉灰区（已由设计阶段定稿，本轮不再讨论）

| 灰区 | 结论 | 出处 |
|---|---|---|
| 布局偏好 | 单列居中、页面不滚动、光学上移、存储提示贴底 | DESIGN §三 |
| 信息密度 | 全页只有剩余时间是大字；三块只靠留白分组 | DESIGN §1.2、§三 |
| 交互方式 | 两个原生按钮；无快捷键、无弹窗；按键只用于「我看到提醒了」 | Feature Spec R3、§六 |
| 空状态 | 专注 25:00、今天完成 0 个、主按钮「开始」 | DESIGN §6.1 |
| 动效风格 | 全页唯一过渡是按钮悬停变色；「减少动态效果」时取消 | DESIGN §5.2 |

## 工程灰区（本轮收拢）

| # | 灰区 | 推荐（采用） | 备选 | 理由 |
|---|---|---|---|---|
| G1 | 提示音怎么来 | 浏览器自带音频能力现场合成一声短促柔和的音，不放音频文件 | 内置一个小音频文件 | 不加文件、不加外部资源；音色好调；Feature Spec 允许工程自选 |
| G2 | 文件怎么分 | 根目录 `index.html` + 样式文件 + 两个脚本：纯计时规则（不碰页面，可单独测）和页面接线；用普通脚本引入，不用模块写法 | 一个大脚本 | 本地双击打开时浏览器不允许加载模块脚本；规则单独成文件才好测 |
| G3 | 怎么测 | 计时规则用 Node 自带的测试工具做单元测试（不装任何依赖）；页面行为交给 forge-qa 用浏览器自动化实测 | 引入测试框架 | PRD 要求无第三方依赖、无构建步骤 |
| G4 | 本地怎么预览 | 用系统自带的 Python 起一个静态服务给 QA 用，显式端口、记录进程；另验证双击 `index.html` 也能用 | 引入开发服务器工具 | 项目没有统一的开发服务入口，也不需要 |

演示时由 AI 按默认确认：四个工程灰区全部采用推荐方案；视觉灰区沿用 DESIGN.md，不再重开。

## 传给下游的硬约束

1. 不加 Feature Spec 第六节「非目标」里的任何东西（含快捷键、静音开关、自定义时长、系统通知）。
2. 不从外部网址加载任何资源；全部相对路径。
3. 组件样式只写 `var()`；站点语义色与字体写在样式文件的 `:root`，值以 DESIGN §2.1、§2.2 为准；`pomodoro.tokens.css` 不手改。
4. 五个比对锚点 `data-ui="phase|time|primary|skip|count"` 必须存在（DESIGN §七）。
