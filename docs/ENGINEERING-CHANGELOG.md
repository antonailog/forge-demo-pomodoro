# 工程变更日志

## [v1.0] - 2026-10-23

### 变更背景

PRD v1.0 从零定义番茄钟网页（R1 计时与控制、R2 今日完成数、R3 到点提醒、R4 标签页标题、R5 保存与恢复、R6 手机与窄屏）。设计实现阶段（forge-design-impl）已交付 `index.html` 结构和 `style.css`，并在 `style.css` 文件头定下「样式与行为的接口」。本次补上全部行为。

### 技术方案

- 纯规则模块 `timer-core.js`：状态、动作、到点结算、跨零点、恢复、记录校验、页面文字与标题全部是纯函数，时间由参数传入，可在 Node 里单测。
- 页面接线 `app.js`：存储探测与降级、启动恢复、每 250ms 走秒、回到前台与其他页面写入时立即刷新、只在变化时改页面、提示音合成、点击或按键确认提醒。
- 两个脚本都用普通 `defer` 引入，保证本地双击打开可用。
- 单测用 Node 自带测试运行器，不装依赖；页面行为由 forge-qa 用浏览器自动化实测。

### 关键决策

| 议题 | 决定 | 原因 |
|---|---|---|
| 测试框架 | Node 自带 `node --test`（forge-eng 提供的选项里没有这一项，按 CONTEXT G3） | PRD 要求无第三方依赖、无构建步骤 |
| 剩余时间 | 只存结束时刻，显示值现算并夹在 `[0, 本段时长]` | 后台定时器会被放慢；系统时间可能回调 |
| 存储 | 一个键一条 JSON，任何字段不合法整条作废 | Feature Spec R5 错误态「当作没有记录」最简单 |
| 两个页面恢复同一段 | 记录里存「最近计数的结束时刻」，同一段只计一次 | Feature Spec 没写到；不处理会把一段专注算成两个（补齐，演示时按默认确认） |
| 到点提示跨刷新 | 不保留 | Feature Spec 没写到；刷新即视为看到了，最简单（补齐，演示时按默认确认） |
| 到点那一刻按按钮 | 先结算到点，本次点击不执行 | 避免把刚切出来的休息误开始（补齐，演示时按默认确认） |
| 「显示的剩余时间不多于真实剩余时间」 | 按 Feature Spec 组件定义向上取整到秒，即显示值与真实值相差不到一秒 | Feature Spec R4 与「剩余时间」组件定义措辞不一致，以组件定义为准 |
| 提示音 | 正弦波约 660Hz、峰值音量约 0.1、0.8 秒内淡出，主按钮点击时解锁 | 「短促、安静」；DESIGN 待优化项，参数记在 ENGINEERING §三.3 |
| 后台准时响铃 | 不做提前排音或常驻音频 | 先实测晚响程度（PRD P1）；常驻音频违背「安静」 |

### Bug 修复：BF-1023-1 切换阶段时主按钮直接换色（forge-bugfix）

| 问题 | 修正 | 依据 |
|---|---|---|
| 到点或点跳过切换阶段时，主按钮底色走了一次 120ms 过渡（用户反馈「是慢慢变过去的」）；根因是悬停用的 `background-color` 过渡写在按钮常态上，换阶段改同一个属性也会触发，只改样式分不清两种变化（鼠标停在按钮上时到点仍会渐变） | `app.js`：`setAttr` 返回是否真的改了；`data-phase` 真正变化时让主按钮的 `background-color` 过渡立即走完，先判断浏览器有没有 `getAnimations`，不用 `try/catch`。`style.css` 只在文件头接口注释补写这条约定，样式规则不变。回归用例 `scripts/qa/phase-switch-color.mjs`（假时钟 + 冻结动画时间线，零真实等待） | DESIGN §5.1、§5.2；[BF-1023-1 报告](archive/raw/bugfix-reviews/BF-1023-1.md) |

### 上线前审查修正（forge-review）

| 问题 | 修正 | 依据 |
|---|---|---|
| 系统时间往回调后点暂停，存下的剩余时间比本段完整时长还长：页面显示 `25:00`，点继续后数字却停着不动；刷新一次又变回真的 `25:00`，同一状态刷新前后不一致 | `press` 暂停时用 `remainingMs()` 取值，与显示、恢复记录同一口径夹到 `[0, 本段时长]`；U7 原来断言的是旧行为，改为断言新口径并补「继续后马上往下走、存取一遍不变」 | ENGINEERING §三.2「剩余时间一律夹在 `[0, 本段时长]`」；Feature Spec R1 错误态 |
| `app.js` 把页面结构读取、渲染、事件绑定也包进空的 `try/catch`：页面锚点一旦被改坏，按钮会静默失灵、控制台看不到任何错误（原列在 §九 技术债，交审查决定） | 去掉只包页面操作的 `try/catch`，只保留存储和声音两处（浏览器设置可能让它们失败） | ENGINEERING §三.3「控制台」；forge-qa 控制台零错误的前提是错误不被吞掉 |
| 走秒间隔、提示音参数是裸数字 | 提成带注释的常量 `TICK_MS`、`BEEP`，值不变 | ENGINEERING §三.3 |
