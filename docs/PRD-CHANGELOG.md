# PRD 变更日志

## [v1.0] - 2026-10-23

### 变更背景

新项目第一版 PRD。需求经 `/forge-brainstorm` 产品模式讨论收敛（原文：`docs/archive/raw/discussions/番茄钟/2026-10-23-番茄钟-需求讨论.md`，以其 §9.2 为准），本次把讨论结论写成产品当前事实和 Feature Spec。

### 用户原始需求

> 我想做一个番茄钟网页，专心工作 25 分钟、休息 5 分钟，能看到今天完成了几个。

### 设计方案

单页静态番茄钟：固定专注 / 休息循环，开始、暂停、跳过；到点响一声并让标签页标题交替提示；当天完成数和当前这一段都保存在本机浏览器，刷新或浏览器自动重载后接着走；手机上能看能点。无后端、无账号、无第三方依赖。

### 关键决策

| 议题 | 决定 | 原因 |
|------|------|------|
| 产品形态 | 做：纯前端静态单页 | 需求方要「越简单越好、不要后端」，以后可能挂 GitHub Pages |
| 时长设置、长休息 | 不做 | 原话只有两个固定时长；设定外的按最简单处理 |
| 什么算完成 | 只算走到点的专注段 | 「完成」按字面理解，最不容易引起争议 |
| 待开始时能否跳过 | 做：任何状态都能跳过 | 刚专注完想直接再来一段时，不用先开始休息再跳过（PRD 阶段新补） |
| 到点后是否自动开始下一段 | 不自动，停在待开始 | 人不在座位时不会白白开始计时 |
| 提醒方式 | 做：响一声 + 标题交替；不做系统通知 | 系统通知要弹权限框，违背「打开就能用、不打扰」 |
| 标签页标题格式 | 剩余时间放最前面 | 用户主要在别的标签页干活，标题是主要信息出口 |
| 刷新后正在走的一段 | 恢复，不作废 | 浏览器也会自己重新加载页面；作废会让该算的完成数漏记 |
| 离开期间已过点 | 按完成计数，不补响铃 | 补响铃对已经不在场的人没意义，反而突兀 |
| 存储不可用 | 计时照常 + 常驻一行提示 | 不能悄悄丢数据，也不能弹窗打扰 |
| 两个页面同时开 | 各自计时，完成数不互相覆盖 | 不做同步，但保证数据不丢 |
| 手机 | 做：自适应能看能点；不承诺锁屏提醒 | 需求方点名要手机能看；锁屏挂起是浏览器限制 |
| 后台铃声可能晚响 | 记为 P1 风险，QA 实测 | 纯网页无法完全规避，先量再决定要不要加桌面通知 |
