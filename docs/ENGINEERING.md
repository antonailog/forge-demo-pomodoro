## 一、技术栈

### 1.1 核心技术

| 类别 | 技术 | 用途 |
|---|---|---|
| 页面 | 原生 HTML + CSS + JavaScript（主流浏览器原生支持的语法，普通 `defer` 脚本，不用模块写法） | 唯一页面，无框架、无构建、无第三方依赖 |

## 二、架构概览

### 2.1 模块关系

```
                 ┌──────────────────────────── index.html ────────────────────────────┐
                 │  data-ui 文字节点 · body[data-phase] · body[data-storage]           │
                 │  <link> pomodoro.tokens.css, style.css                              │
                 │  <script defer> timer-core.js → app.js（顺序执行，不用 type=module）│
                 └───────────────▲───────────────────────────────────▲─────────────────┘
                                 │ 只改文字、两个属性、document.title │
┌─────────── timer-core.js ──────┴───────┐        ┌──────────────── app.js ──┴──────────────────┐
│ 纯规则，不碰页面、不读时钟（now 由参数传入） │◄───────│ 页面接线                                      │
│ initial / restore / tick / press / skip │ 调用    │ · 存储：探测、读、合并完成数、写；失败即降级    │
│ ack / mergeCounter / parseRecord /      │        │ · 走秒：每 250ms + 回到前台 + 其他页面写入时     │
│ toRecord / remainingMs / formatTime /   │        │ · 渲染：view() 的结果只在变化时写进页面          │
│ view（全部页面文字与标题）               │        │ · 提醒：到点事件 → 提示音；点击/按键 → ack      │
└───────────────▲─────────────────────────┘        └──────────────┬──────────────────────────────┘
                │ require()                                       │ localStorage / AudioContext
     tests/timer-core.test.js（node --test）                       ▼
                                                        浏览器（本机记录、合成音）
```

- **单一状态源**：一个状态对象（当天完成数 + 当前段 + 未确认的到点提示），R1–R5 共用（PRD「关联变更」）。
- **规则即纯函数**：所有状态变化都由 `timer-core.js` 算出「新状态 + 事件」，不修改传入对象；`app.js` 只负责把事件翻译成声音、把状态翻译成页面文字。
- **样式与行为的接口**：照 `style.css` 文件头注释执行——只改 `body[data-phase]`（focus / break）、`body[data-storage]`（ok / off）、五处文字 `[data-ui=phase|time|status|primary|count-num]` 和 `document.title`；不加类名、不写内联样式。

## 三、前端工程

### 3.1 `timer-core.js`：纯规则

浏览器里挂到 `window.PomodoroCore`；Node 里 `module.exports`（文件末尾判断 `typeof module`）。

**状态对象**（内存）：

| 字段 | 取值 | 说明 |
|---|---|---|
| `date` | `'YYYY-MM-DD'` | 完成数属于哪一天（本机日期） |
| `count` | 非负整数 | 这一天走到点的专注段数 |
| `countedEndAt` | 毫秒时间戳或 `null` | 最近一次计数的那段专注的结束时刻，用于同一段只计一次（§3.2） |
| `phase` | `'focus'` / `'break'` | 当前段阶段 |
| `status` | `'idle'` / `'running'` / `'paused'` | 待开始 / 进行中 / 已暂停 |
| `endAt` | 毫秒时间戳或 `null` | 仅进行中有值 |
| `remainingMs` | 毫秒数或 `null` | 仅已暂停有值 |
| `alert` | `null` 或 `{ phase, at }` | 未确认的到点提示（哪一段结束、何时）；**不保存** |

**函数**（`now` 一律由调用方传入毫秒时间戳）：

| 函数 | 作用 |
|---|---|
| `FOCUS_MS` / `BREAK_MS` | 25 分钟 / 5 分钟 |
| `dateKey(ms)` | 本机日期 `'YYYY-MM-DD'` |
| `initial(now)` | 专注待开始、今天 0 个 |
| `parseRecord(text)` | 存储里的字符串 → 合法记录；任何字段不合法返回 `null` |
| `toRecord(state)` | 状态 → 要保存的记录（`v: 1`，不含 `alert`） |
| `restore(record, now)` | 打开页面时恢复；离开期间到点**静默结算**（计数、切段，不产生事件、不设提示） |
| `tick(state, now)` | 走秒 / 回到前台时调用：到点结算（产生 `complete` 事件、设提示）+ 跨零点归零；返回 `{ state, events }` |
| `press(state, now)` | 主按钮：开始 / 暂停 / 继续；先做一次 `tick`，若这一刻刚好到点，只结算、不执行按钮动作 |
| `skip(state, now)` | 跳过：先 `tick`（同上），再切到另一阶段待开始，不计数、无事件 |
| `ack(state)` | 用户在页面上点击或按键：清除未确认的到点提示 |
| `mergeCounter(state, record)` | 用存储里的最新记录合并完成数：同一天取大者，日期新的为准 |
| `remainingMs(state, now)` | 剩余毫秒，夹在 `[0, 本段时长]` |
| `formatTime(ms)` | 向上取整到秒，输出 `mm:ss` |
| `view(state, now)` | 页面要显示的全部内容：`{ phase, phaseLabel, time, status, primary, count, title }` |

### 3.2 规则口径（与 Feature Spec 的对应）

| 规则 | 实现 | Feature Spec |
|---|---|---|
| 剩余时间 | 进行中 = `endAt − now`，暂停 = `remainingMs`，待开始 = 本段时长；一律夹在 `[0, 本段时长]`，显示向上取整到秒 | R1、§二 剩余时间 |
| 到点结算 | `now ≥ endAt` 时：专注 → 计数（规则见下）后切到休息待开始；休息 → 切到专注待开始 | R1、R2 |
| 计数归属 | 归到**结束时刻**所在的本机日期：与记录日期相同则加一；更新的日期则该日记 1；更早的日期不改今天 | R2 跨零点 |
| 同一段只计一次 | 结算专注时若 `endAt === countedEndAt`，不再加一（两个页面恢复的是同一段时会各自到点） | R5 两个页面（补齐） |
| 跨零点 | 每次 `tick` / `restore`：记录日期不是今天 → 今天 0 个 | R2、R5 陈旧态 |
| 离开期间到点 | `restore` 静默结算：计数、切到下一段待开始，不响铃、标题不交替；那段在今天之前就结束了 → 直接回到专注待开始 | R5 |
| 按钮与到点同时发生 | 先结算到点，本次点击不再开始 / 暂停（避免把刚切出来的休息误开始） | R1 连续快速点击（补齐） |
| 到点提示 | `tick` 结算时设 `alert`；`press` / `skip` / `ack` 清除；**不跨刷新保留** | R3、R4 陈旧态（补齐） |
| 标题 | 进行中 `mm:ss · 专注|休息`；已暂停 `mm:ss · 已暂停`；待开始 `番茄钟 · 今天 N 个`；有未确认提示时按「提示出现后经过的整秒数」奇偶在「专注结束！ / 休息结束！」与待开始标题之间交替（每 1 秒） | R4、DESIGN §5.1 |
| 状态说明 | 有未确认提示 → 专注结束 / 休息结束；已暂停 → 已暂停；其余为空 | DESIGN §4.3 |
| 记录不合法 | `parseRecord` 返回 `null` → 按第一次打开处理，随后立即写回合法记录 | R2、R5 错误态 |

### 3.3 `app.js`：页面接线

| 关注点 | 做法 |
|---|---|
| 启动 | 探测存储（写一个探测键再删掉）→ 读记录 → `restore` → 立即保存一次（顺便改正不合法记录）→ 渲染 → 启动走秒 |
| 走秒 | `setInterval` 每 250ms：到点前先从存储同步完成数 → `tick` → 有变化就保存 → 渲染；`visibilitychange`（变为可见）、`pageshow` 时立即做一次 |
| 多页面 | 监听 `storage` 事件：其他页面写入后合并完成数并重新渲染；保存前先合并存储里的完成数，不会用旧数覆盖别的页面写入的数；两个页面的计时不同步 |
| 存储降级 | 访问、读、写 `localStorage` 全部 `try/catch`（`try/catch` 只用在存储和提示音两处，页面结构出错直接在控制台暴露）；探测或任意一次写入失败 → `body[data-storage]="off"`，底部提示出现，计时照常，完成数只在本次打开期间累计 |
| 渲染 | `view()` 的结果逐项与上次比较，只在变化时写文字、属性、标题 |
| 提示音 | 主按钮被点击时创建或 `resume()` 一个 `AudioContext`（网页出声需要用户先操作）；收到 `complete` 事件且 `AudioContext` 处于运行状态时合成一声：正弦波约 660Hz、峰值音量约 0.1、约 20ms 淡入、约 0.8 秒内淡出；从没点过主按钮、浏览器拦截、任何异常都静默跳过，`resume()` 的 Promise 一律 `.catch` |
| 确认看到提醒 | `document` 上捕获阶段监听 `pointerdown`、`keydown`：有未确认提示时 `ack` 并渲染；按键只用来确认，不触发开始 / 暂停（快捷键是非目标） |
| 控制台 | 不调用 `console.error`；没有未处理的 Promise 拒绝 |

### 3.4 状态管理

| 状态 | 存储方式 | 更新时机 |
|---|---|---|
| 当天完成数、当前段 | 内存状态 + `localStorage['pomodoro.v1']` 一条 JSON | 每次状态变化（按钮、到点、跨零点）后写一次 |
| 未确认的到点提示 | 只在内存 | 到点时设，点击 / 按键 / 按按钮时清 |
| 存储是否可用 | 只在内存，反映到 `body[data-storage]` | 启动探测、每次写入失败 |
| `AudioContext` | 只在内存 | 主按钮点击时创建或恢复 |

单页，无路由。

## 四、后端工程

无。不引入任何服务器、接口或账号体系（PRD §六）。

### 4.1 本机数据模型

`localStorage` 键 `pomodoro.v1`，值为一条 JSON：

```json
{ "v": 1, "date": "2026-10-23", "count": 3, "countedEndAt": 1761236100000,
  "phase": "break", "status": "idle", "endAt": null, "remainingMs": null }
```

合法性（`parseRecord`）：`v` 为 1；`date` 形如 `YYYY-MM-DD`；`count` 为非负整数；`countedEndAt` 为有限数字或 `null`；`phase`、`status` 在取值范围内；进行中必须有有限的 `endAt`；已暂停必须有大于 0 的有限 `remainingMs`（超过本段时长按本段时长）。任何一条不满足 → 整条当作没有记录。

## 五、数据流

### 5.1 点「开始」到专注到点

```
点击主按钮
  → 解锁提示音（创建 / resume AudioContext）
  → 从存储同步完成数 → press(state, now)：endAt = now + 25 分钟
  → 保存记录 → 渲染：主按钮「暂停」、标题「25:00 · 专注」
每 250ms
  → tick(state, now)：显示值 = ceil((endAt − now) / 1000) 秒
  → 跨秒才改文字和标题
now ≥ endAt（前台或后台，后台可能被浏览器推迟）
  → 结算前从存储同步完成数（别的页面可能已加过）
  → tick：完成数 +1（同一段不重复）、切到「休息 05:00」待开始、alert = 专注结束、事件 complete
  → 保存记录 → 提示音一声 → 渲染：状态说明「专注结束」，标题每秒交替
用户在页面上点击或按键
  → ack：清除 alert → 状态说明消失，标题「番茄钟 · 今天 N 个」
```

### 5.2 刷新 / 关掉重开

```
读记录 → parseRecord（不合法 → 没有记录）
  → restore(record, now)
       进行中未到点 → 接着走；已暂停 → 保持；待开始 → 保持
       进行中已过点 → 静默结算（计数归到结束那天）→ 下一段待开始；那段在今天之前结束 → 专注待开始
       记录日期不是今天 → 今天 0 个
  → 立即保存一次 → 渲染（没有提示音、标题不交替）
```

| U17 | 恢复：进行中未到点 / 已暂停 / 待开始 | 接着走 / 保持暂停 / 保持 | R5 正常 |
| U18 | 恢复：离开期间专注到点（同一天，2 个） | 3 个、休息 `05:00` 待开始、无提示、标题 `番茄钟 · 今天 3 个` | R5 异常 |
| U19 | 恢复：那段在昨天就结束了 | 今天 0 个、专注 `25:00` 待开始 | R5 边界 |
| U20 | 两个页面：页面里是旧数 3、存储里是 4，再到点 | 5；同一段被两个页面各结算一次只算一次 | R5 两个页面 |
| U21 | 按钮与到点同时发生 | 只结算到点，不开始休息 | §三.2 |
| U22 | 纯函数 | 所有函数不修改传入对象 | §二.1 |

**forge-eng 自验范围**：U 组全部自动化；E1–E16 已由 forge-eng 用本机 Playwright 逐条自验通过（自验脚本不进仓库），forge-qa 仍需按验收检查表独立执行；M1–M3 只能真实等待或真机，forge-eng 未测。

**给 forge-qa 的测法提示**（不需要页面里的测试钩子）：

- 快进时间：Playwright `page.clock.install({ time })` 后用 `runFor` / `fastForward`，页面里的 `Date.now()` 与 `setInterval` 一起被接管。
- 禁用存储：`context.addInitScript` 里把 `window.localStorage` 改成访问即抛 `SecurityError` 的 getter。
- 数提示音：`addInitScript` 包一层 `AudioContext`，统计 `createOscillator` 调用次数；或让构造函数抛错模拟被拦截。
- 记录键名 `pomodoro.v1`，格式见 §四.1，可直接写入构造「离开期间到点」「昨天的记录」「损坏记录」。

## 八、故障模式与运行边界

| 新代码路径 | 现实中的失败方式 | 有测试 | 有处理 | 用户看到什么 |
|---|---|---|---|---|
| 走秒 / 到点 | 后台标签页定时器被浏览器放慢，最长可到约一分钟一次 | M1 | 回到前台、页面可见时立即结算；不靠逐秒累减 | 铃声晚响（已知边界，QA 记录晚多少） |
| 走秒 / 到点 | 电脑睡眠，唤醒后才执行 | U9、E13、M2 | 结算按结束时刻判断 | 唤醒后立即显示真实状态 |
| 剩余时间 | 系统时间被往回调 | U7 | 夹到本段时长 | 显示 `25:00` / `05:00`，不报错 |
| 存储 | 隐私模式禁用、站点数据被禁、空间满 | E9 | 全部 `try/catch`，降级为只在内存 | 底部存储提示，计时照常 |
| 存储 | 记录被改坏或旧版本格式 | U15、E8 | 整条当作没有记录并写回合法记录 | 第一次打开的样子，无错误 |
| 多页面 | 两页同时到点、或用旧数覆盖新数 | U20、E10 | 结算前、保存前合并存储里的完成数；同一段只计一次 | 完成数正确 |
| 提示音 | 没点过按钮就到点（刷新后恢复出进行中）、浏览器拦截 | E11 | 静默跳过，Promise 全部 `.catch` | 只靠标题交替和状态说明 |
| 提示音 | 系统音量为零、耳机断开 | 无 | 无法感知 | 听不到（靠标题交替兜底） |
| 脚本加载 | `file://` 下模块脚本被拦截 | E16 | 不用 `type="module"` | 双击打开正常 |
| 按钮 | 到点那一刻按下主按钮 | U21 | 先结算到点，本次点击不执行 | 看到「休息 05:00 待开始」而不是误开始休息 |

没有「无测试 + 无处理 + 静默失败」的严重缺口；「系统音量为零」无法由页面感知，靠标题交替兜底。

## 九、未纳入范围与已知技术债

| 项 | 原因 |
