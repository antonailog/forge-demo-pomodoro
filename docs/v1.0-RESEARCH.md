# 技术调研报告 — v1.0

## 调研时间：2026-10-23
## 调研范围：PRD v1.0 全部六块（R1 计时与控制、R2 今日完成数、R3 到点提醒、R4 标签页标题、R5 保存与恢复、R6 手机与窄屏），纯静态前端

> forge-dev 第 2 步产物，传给 forge-design-impl、forge-eng、forge-qa。上游：[v1.0-CONTEXT.md](v1.0-CONTEXT.md)。迭代结项后归档到 `docs/archive/raw/`。

### 一、技术方案推荐

| 关注点 | 推荐 | 依据 |
|---|---|---|
| 页面技术 | 原生 HTML + CSS + JavaScript，无框架、无构建、无依赖 | PRD §六 |
| 脚本加载 | 普通 `<script src="…" defer>`，**不用** `type="module"` | 本地双击打开（`file://`）时浏览器按跨域拦截模块脚本，页面会直接不工作 |
| 计时 | 只存「结束时刻」，显示值 = 结束时刻 − 现在，向上取整到秒，夹在 0 与本段完整时长之间 | 后台标签页的定时器会被浏览器放慢；系统时间回调时要防止超过完整时长 |
| 刷新节奏 | 前台用短间隔定时器（亚秒级）检查是否跨秒，只在显示值变化时改 DOM；`visibilitychange` 变为可见时立即重算 | 避免走秒漏秒；回到前台立即显示真实值（R1 边界） |
| 提示音 | `AudioContext` 现场合成一声短促、低音量、带淡入淡出的正弦音；在点「开始」时创建或 `resume()` | 网页要先有用户操作才能出声；合成音不需要文件（CONTEXT G1） |
| 本地存储 | `localStorage` 一个键存一条 JSON 记录；启动时用「写一个探测键再删掉」判断能否保存 | 隐私模式、禁用站点数据、空间满时读写会抛异常 |
| 多页面 | 完成计数时先从存储里读最新值再加一；监听 `storage` 事件和回到前台时刷新完成数 | R5「两个页面不互相覆盖」 |

### 二、架构模式推荐

```
index.html（结构 + data-ui 锚点）
  ├─ pomodoro.tokens.css（工作台导出，勿手改）
  ├─ style.css（:root 站点语义色与字体 + 组件样式，只写 var()）
  ├─ timer-core.js（纯规则：状态、动作、到点判定、恢复、格式化、标题文案；不碰 DOM、不读时钟，时间由参数传入）
  └─ app.js（页面接线：读写存储、定时检查、渲染、提示音、标题交替、事件）
tests/（Node 自带测试运行器，只测 timer-core.js）
```

- **单一状态源**：当前段 `{ phase, status, endAt | remainingMs }` + `{ date, count }`。R1–R5 共用这一份状态（PRD「关联变更」）。
- **规则即纯函数**：`start / pause / resume / skip / tick(now) / restore(saved, now)` 都返回「新状态 + 事件（如到点、完成数加一）」。页面层只负责把事件翻译成声音、标题、DOM。
- **样式与行为的接口**：页面层只改 `data-*` 属性和文字；样式只根据属性切换。建议属性：`data-phase="focus|break"`（阶段色）、`data-status`（状态说明是否有字）、`data-storage="off"`（存储提示是否出现）。具体名字由 forge-design-impl 定，forge-eng 照用。
- **双模块导出**：`timer-core.js` 末尾判断 `typeof module !== 'undefined'` 时导出给 Node 测试，否则挂到 `window`，一份代码两处可用。

### 三、风险与坑点

| 坑 | 后果 | 规避 |
|---|---|---|
| 后台标签页定时器被放慢，长时间隐藏后可能放慢到大约一分钟一次 | 后台到点铃声晚响、标题更新慢 | 不靠逐秒累减；回到前台立即处理；**不用**循环播放静音音频之类的手段绕过（违背「安静」和浏览器意图）。晚响程度交给 QA 实测记录（Feature Spec R3） |
| 提示音在没有用户操作的页面上被拦截 | 恢复出来的进行中段到点时不响 | `play` 全程 try/catch，`resume()` 的 Promise 必须 `.catch`；不得出现未处理的 Promise 拒绝（QA 对控制台错误零容忍） |
| 读 `window.localStorage` 这个属性本身就可能抛异常 | 页面整体报错白屏 | 访问、读、写全部包 try/catch；失败即进入「不能保存」降级 |
| 记录损坏或字段不合法 | 显示 NaN、负数 | 读出后逐字段校验；不合法整条丢弃并覆盖为合法记录 |
| 跨零点 | 昨天的数显示在今天 | 完成数挂在「本段结束时刻的本机日期」上；渲染时比较记录日期与今天 |
| 系统时间被往回调 | 剩余时间超过本段完整时长 | 显示值夹到完整时长 |
| 连续快速点主按钮 | 状态错乱 | 每次点击同步算出新状态，不依赖定时器回调 |
| 按任意键停止标题交替 | 被误做成快捷键 | 按键只用于「确认看到提醒」，不触发开始、暂停（快捷键是非目标） |
| 手机横屏高度不够 | 「专注」被顶出屏幕 | DESIGN §2.6 矮屏规则 `@media (max-height: 479px)` |
| 字体数字宽度不一 | 走秒左右跳 | `font-variant-numeric: tabular-nums` |

### 四、可复用资产

| 资产 | 用法 |
|---|---|
| 根目录 `pomodoro.tokens.css` | 页面直接引入；站点语义色按 DESIGN §2.1 补在 `:root` |
| 工作台骨架 `docs/assets/visuals/pomodoro/2026-10-23-skeleton-v1.0.html` | 结构与比例参照；实现后对比 |
| `docs/assets/visuals/pomodoro/pomodoro.tokens.json` 的 `implCheck` | forge-design-lab 的 `compare_impl.mjs` 按五个 `data-ui` 锚点比对骨架与真页面位置尺寸；配置里的页面地址是本机 `127.0.0.1:4577/index.html`，预览服务用这个地址即可直接比对 |
| `scripts/design-doc/pomodoro-shots.mjs` | forge-feature-doc 换真实截图时可参照 |
| 本机 Playwright（含时钟控制能力） | QA 用来快进时间、模拟跨零点、模拟存储被禁用 |

项目里还没有任何页面代码，无可复用的业务代码。

### 五、综合建议

1. 先由 forge-design-impl 产出 `index.html` 结构和 `style.css`，用属性开关覆盖全部视觉状态，并把属性名写清楚交给 forge-eng。
2. forge-eng 先写 `timer-core.js` 的失败测试再实现（规则是这次最容易错的地方），再写 `app.js` 接线。
3. forge-qa 重点测：后台到点（真实等待并记录晚响）、刷新与离开期间到点、跨零点、存储被禁用、两个页面、手机竖屏与横屏、控制台零错误。
